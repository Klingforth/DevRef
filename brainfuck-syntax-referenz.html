Brainfuck – 8 Befehle, unendliche Möglichkeiten 
Brainfuck von Urban Müller (1993) – ursprüngliches Ziel:
kleinster Amiga Compiler (Original: 240 Bytes!)
Alles was kein Befehl ist (> < + - . , [ ]) ist ein Kommentar.

Das Speichermodell:
  [ 0 | 0 | 0 | 0 | 0 | 0 | ... ]  30.000+ Byte-Zellen
        ^
        Zeiger (startet hier)

Jede Zelle enthält einen Byte-Wert (0–255).
Überlauf: 255 + 1 = 0  (wraparound!)
           0 - 1 = 255  (wraparound!)

Das erste BF-Programm:
+++.

Schritt 1: +   → Zelle 0 = 1
Schritt 2: +   → Zelle 0 = 2
Schritt 3: +   → Zelle 0 = 3
Schritt 4: .   → Ausgabe: ASCII 3 (kein druckbares Zeichen)

Besser: ASCII 65 = 'A'
++++++++[>++++++++<-]>.

Lies: Zelle 0 = 8, dann Schleife: 8 mal (Zelle 1 += 8, Zelle 0 -= 1)
Ergebnis: Zelle 1 = 64, dann +1 = 65 = 'A', dann ausgeben!

Äquivalentes C:
++++++++[>++++++++<-]>.
int ptr = 0, mem[30000] = {0};
mem[0] = 8;
while (mem[0]) { mem[1] += 8; mem[0]--; }
ptr = 1;
mem[1]++;
putchar(mem[1]);
Das Speichermodell visualisiert 
Startzustand:
  Zellen: [ 0  | 0  | 0  | 0  | 0  ]
            ^
          Zeiger (ptr = 0)

Nach "++>+++>+":
  Befehl: + +  > + + +  > +
  Zellen: [ 2  | 3  | 1  | 0  | 0  ]
                       ^
                     Zeiger (ptr = 2)

Nach "<.":
  Befehl: <  .
  Zeiger geht zu Zelle 1 (Wert=3)
  Ausgabe: ASCII 3 (ETX – kein druckbares Zeichen)

Um 'A' (ASCII 65) auszugeben:
  Brauche ich 65 × '+' oder besser: Multiplikation!

Schleifen erklären:
  [  ...  ]
  ↑         ↑
  Wenn aktuell == 0: SPRINGE zu ]
             Wenn aktuell != 0: SPRINGE zu [

[ Inhalt ]  =  while (*ptr != 0) { Inhalt }

Verschachtelung ist erlaubt:
  [ äußere [ innere ] Schleife ]
  Klammern müssen IMMER ausbalanciert sein!

Alle anderen Zeichen (Buchstaben, Zahlen, Leerzeichen, Newlines):
  Werden KOMPLETT IGNORIERT.
  Das macht Kommentare einfach: einfach hinschreiben!

Wichtige Details:
+ auf 255 → wird zu 0 (Überlauf/Wraparound)
- auf 0 → wird zu 255 (Unterlauf/Wraparound)
[ und ] müssen immer ausgeglichen sein (wie Klammern)
, bei EOF: implementierungsabhängig (0, -1 oder keine Änderung)
Zeiger > oder < über Grenzen: implementierungsabhängig (Wrap oder Fehler)
+++ Zelle 0 = 3 (drei mal +1)
+++++++ Zelle 0 = 7 (sieben mal +1)
>++ Zeiger zu Zelle 1, Zelle 1 = 2
< Zeiger zurück zu Zelle 0
[-] Zelle auf 0 setzen (Schleife bis Null)
[->+<] Wert von Zelle 0 zu Zelle 1 addieren
. ASCII-Wert der aktuellen Zelle ausgeben
, Ein Zeichen von Stdin lesen
[.,] Zeichen lesen und ausgeben bis EOF (cat-Programm!)
[-] Schleife: -1 bis Null → garantiert Zelle = 0
[+] Alternative (über 256 wrappen) – langsamer
[->+<] Von Zelle A nach B: A mal: A-1, B+1
[->+>+<<] Kopieren nach B UND C (A wird dabei zu 0)
[->+>+<<] A nach B und C kopieren (A wird 0)
>>[-<<+>>] C zurück nach A (B enthält Kopie, A wiederhergestellt)
[Aktion[-]] Führe Aktion aus wenn A != 0, dann A auf 0 setzen
[[-]Aktion] Alternative Formulierung
[->+<] Standard: A in B addieren, A leeren
[->+>+<<]>>[-<<+>>] A nach B&C, dann C nach A → A unverändert, B = A+B
++++++++[>++++++++<-]>. 8 × 8 = 64, dann +1 = 65 = "A"
++++++++++[>+++++++<-]>. 10 × 7 = 70... Multiplikation für effiziente Konstanten
++++++++++++++++++++++++++++++++ . 32 mal + dann . (naiv)
[>++++++++<-]>. Besser: 4×8=32 via Schleife
Brainfuck-Interpreter in Python 
# Einen vollstaendigen BF-Interpreter in Python schreiben
# Zeigt wie simpel BF wirklich ist!

def brainfuck(code, eingabe=""):
    """Fuehrt Brainfuck-Code aus."""
    # Nur gueltige BF-Zeichen behalten
    code = [c for c in code if c in "><+-.,[]"]

    # Speicher und Zeiger initialisieren
    zellen = [0] * 30000
    ptr = 0          # Zellen-Zeiger
    ip  = 0          # Instruction Pointer
    eingabe_pos = 0  # Position in Eingabe-String

    # Klammer-Mapping vorberechnen (effizient!)
    klammern = {}
    stack = []
    for i, c in enumerate(code):
        if c == "[":
            stack.append(i)
        elif c == "]":
            j = stack.pop()
            klammern[j] = i   # [ -> ]
            klammern[i] = j   # ] -> [

    ausgabe = []

    while ip < len(code):
        befehl = code[ip]

        if   befehl == ">":
            ptr = (ptr + 1) % 30000    # Zeiger rechts
        elif befehl == "<":
            ptr = (ptr - 1) % 30000    # Zeiger links
        elif befehl == "+":
            zellen[ptr] = (zellen[ptr] + 1) % 256   # +1, wrap
        elif befehl == "-":
            zellen[ptr] = (zellen[ptr] - 1) % 256   # -1, wrap
        elif befehl == ".":
            ausgabe.append(chr(zellen[ptr]))         # Ausgabe
        elif befehl == ",":
            if eingabe_pos < len(eingabe):
                zellen[ptr] = ord(eingabe[eingabe_pos])
                eingabe_pos += 1
            else:
                zellen[ptr] = 0   # EOF = 0
        elif befehl == "[":
            if zellen[ptr] == 0:
                ip = klammern[ip]   # Springe zu ]
        elif befehl == "]":
            if zellen[ptr] != 0:
                ip = klammern[ip]   # Springe zu [

        ip += 1

    return "".join(ausgabe)

# Testen!
hallo = "++++++++[>++++[>++>+++>+++>+<<<<-]>+>+>->>+[<]<-]>>.>---.+++++++..+++.>>.<-.<.+++.------.--------.>>+.>++."
print(brainfuck(hallo))       # Hello World!

echo = ",."
print(brainfuck(echo, "A"))   # A

Brainfuck-Interpreter in Brainfuck 
Ja, das existiert wirklich.
Ein Brainfuck-Interpreter geschrieben in Brainfuck.
Das Programm ist lang (~500 Zeichen), aber es funktioniert.

Konzeptionell (wie es funktioniert):
- Der BF-Code wird als ASCII-Zeichen eingelesen
- Eine BF-Implementierung verarbeitet den eingelesenen Code
- Das ist ein QUINE-aehnliches Konzept (Selbstbezug)

Warum ist das moeglich?
Weil BF Turing-vollstaendig ist, und eine Turing-Maschine
kann jeden anderen Berechner simulieren - einschliesslich
sich selbst.

Das nennt man einen "Universal Interpreter" -
ein Programm das andere Programme derselben Sprache ausfuehrt.

Die eigentliche Frage die BF aufwirft:
Welches ist das MINIMALE System das noch Turing-vollstaendig ist?

Antwort: Noch kleiner als BF!
- BCT (Binary Cyclic Tag) - reicht
- Zeckendorf Representation
- Rule 110 Zellularautomat (auch Turing-vollstaendig!)

BF ist also nicht minimal - aber der kleinste PRAKTISCHE
esoterische Sprache-Designpunkt.

PROGRAMME (kompakt, klassisch):
++++++++[>++++[>++>+++>+++>+<<<<-]>+>+>->>+[<]<-]>>.>---.+++++++..+++.>>.<-.<.+++.------.--------.>>+.>++.

SCHRITT FUER SCHRITT:
++++++++               p0 = 8  (aeusserer Zaehler)
[                      Schleife 8 mal:
  >++++                  p1 += 4
  [                      Innere Schleife 4 mal:
    >++                    p2 += 2   (wird 64 = 8*4*2)
    >+++                   p3 += 3   (wird 96 = 8*4*3)
    >+++                   p4 += 3   (wird 96 = 8*4*3)
    >+                     p5 += 1   (wird 32 = 8*4*1)
    <<<<-                  p1 -= 1
  ]
  >+                     p2++ -> 72 = H
  >+                     p3++ -> 101 = e
  >-                     p4-- -> 108 = l (96+12-8+... komplex)
  >>+                    p6 = 1  (Newline-Hilfszelle)
  [<]                    gehe zur ersten Null-Zelle
  <-                     p0 -= 1
]

Danach: Verschiedene Zellen enthalten die ASCII-Werte
        H(72) e(101) l(108) l(108) o(111) und Sonderzeichen

>>.          Zeiger zu p2 (=72), ausgeben: H
>---.        p3 - 3 = 98... warte, das ist 'b'?
             Nein! Der Anfangswert muss vorher stimmen.

Ehrlich: Korrektes Hello World ist SEHR muehsam manuell zu verfolgen.
Das zeigt: BF ist leicht ZU LESEN aber schwer ZU SCHREIBEN!

Einfachstes moegliches "A" ausgeben:
++++++++[>++++++++<-]>+.
(8 * 8 = 64, +1 = 65 = 'A')
ZWEI ZAHLEN ADDIEREN: p0 + p1 -> p1 (p0 wird 0)

Beispiel: 3 + 4 = 7

+++          p0 = 3  (erste Zahl)
>            gehe zu p1
++++         p1 = 4  (zweite Zahl)
<            zurueck zu p0
[->+<]       Schleife: p0 mal (p0--, p1++)
             Ergebnis: p0 = 0, p1 = 7

Als Ausgabe:
+++>++++<[->+<]>+++++++[<+++++++>-]<+.
  p0=3, p1=4, addiere -> p1=7
  dann p1 + 48 + 1 = 56... Moment

EINFACHER: Zahlen als ASCII-Zeichen lesen, addieren, ausgeben

,           lese '3' (ASCII 51) in p0
>           zu p1
,           lese '4' (ASCII 52) in p1
[-<+>]      addiere p1 zu p0 (p0 = 103 = 'g'... das ist falsch)

Das Problem: ASCII-Ziffern addieren ist nicht trivial in BF!
'3' = 51, '4' = 52, 51+52 = 103 != '7' (55)
Man muesste 48 ('0') abziehen, addieren, dann 48 wieder addieren.

MULTIPLIKATION: 3 × 4 = 12 in p2
+++          p0 = 3  (Zaehler)
>++++        p1 = 4  (Multiplikator)
<            zurueck zu p0
[            Schleife (3 mal):
  >          zu p1
  [          Schleife (4 mal):
    ->+>+<   p1--, p2++, p3++ (p3 als Temp)
    <
  ]
  >>[-<<+>>] p3 zurueck zu p1 wiederherstellen
  <<         zurueck zu p0
  -          p0--
]
>> p2 enthaelt nun 12 (3*4)

ESOTERISCHE SPRACHEN DIE AUF BF BASIEREN:

OOK! (Duck-Variante von BF)
  Jeder Befehl besteht aus zwei "Ook."/"Ook?"/"Ook!" Tokens:
  Ook. Ook? = >
  Ook? Ook. = <
  Ook. Ook. = +
  Ook! Ook! = -
  Ook! Ook. = .
  Ook. Ook! = ,
  Ook! Ook? = [
  Ook? Ook! = ]

  Hello World in Ook:
  Ook. Ook? Ook. Ook? Ook. Ook? Ook. Ook? Ook. Ook? Ook. Ook? ...
  (Sehr viel laenger als BF)

WHITESPACE
  Programm besteht NUR aus Leerzeichen, Tabs und Newlines.
  Alle anderen Zeichen sind Kommentare.
  Sieht wie eine leere Datei aus!

MALBOLGE (1998, Ben Olmstead)
  Bewusst so schwer wie moeglich designt.
  Kein einziges Programm wurde im ersten Jahr geschrieben.
  Das erste Hello World wurde durch Suche gefunden (nicht manuell!).
  Gilt als haerteste Programmiersprache der Welt.

PIET (David Morgan-Mar)
  Bilder als Quellcode! Pixel-Farben = Befehle.
  Laeuft "durch" das Bild wie ein Flussdiagramm.
  Man kann buchstaeblich ein Mondrian-Gemaelds als Programm ausfuehren.

BEFUNGE (Chris Pressey, 1993)
  Zweidimensionaler Coderaum. Steuerung laeuft in alle 4 Richtungen.
  < > ^ v = Richtungsbefehle
  @ = Ende
  Ermoeglicht unendliche Schleifen ohne [ ]

COW
  12 Befehle, alle klingen wie Kuh-Moegen:
  moo MoO moO mOo MOO OOO MMM OOM oom
  Jeder Befehl hat eine andere BF-entsprechung

CHEF (David Morgan-Mar)
  Rezepte als Quellcode!
  "Cake" ist ein echtes laufendes Programm.
  Stacks heissen "mixing bowls", Ausgabe ist "baking dish".
